# Deviation log

The Part-2 brief (item 2i) says: "Deviations from the submitted document should be documented and explained during the final demo." This log lists every way the build differs from the **submitted** documents: SRS v1.1, SAD v1.0 and Software Test Plan v1.0.

The submitted documents are not revised. Every correction, definition or interpretation the build needs is recorded here instead, so this log is the single record of how the build differs from them.

Each pull request that introduces a difference adds a row. Code comments that cite the "SRS v11 draft" or "SAD v1.10 draft" refer to the team's internal working notes; any rule from them that the build relies on is spelled out in a row below, so it can be traced without the drafts.

Errors in the submitted documents that don't change the build yet are listed in the second table, with the issue that must add a row when it builds that part.

**Status:**
- **Temporary**: closed by a later issue.
- **Permanent**: a deliberate decision, explained here.
- **Open**: still needs a team decision.
